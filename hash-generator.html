How hashing works

A hash function turns any input into a fixed-length fingerprint. The same text always produces the same digest, and even a one-character change gives a completely different result. Hashes are one-way: you cannot recover the original text from a digest.

Picking an algorithm

  • SHA-256: the safe default for checksums and file verification.
  • SHA-512: longer digest, stronger, slightly slower.
  • SHA-1: legacy; fine for change detection, not for security.
  • MD5: fast; fine for non-security uses like cache keys, never for passwords.

Hash generator FAQs

What is a hash function?
A hash function turns any input into a fixed-length fingerprint. The same input always produces the same hash, and even a one-character change produces a completely different result. Hashes are one-way: you cannot get the original text back from a hash.
Which hash should I use: MD5, SHA-1, SHA-256 or SHA-512?
SHA-256 is the safe default for checksums and file verification. SHA-512 is stronger still. MD5 and SHA-1 are fast and fine for non-security uses like change detection, but they are broken for security purposes and should not protect passwords.
Is my text uploaded anywhere?
No. MD5 is computed with JavaScript and the SHA family with the browser's WebCrypto API. Nothing you type leaves your device.
Why do the SHA hashes need HTTPS?
The WebCrypto API is only exposed in secure contexts: pages served over HTTPS or localhost. On plain HTTP the SHA digests are unavailable, but MD5 still works because it is plain JavaScript.
Can I hash a file instead of text?
This tool hashes text. For file checksums you can paste the file's content as text for small files, or use your operating system's built-in checksum command for large ones.
