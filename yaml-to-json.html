How it works

The js-yaml parser reads your YAML into a JavaScript object, then the page prints it as indented JSON. Multi-document YAML (separated by ---) becomes a JSON array of documents. Dates and special types are converted to their JSON-friendly forms.

Fixing parse errors

  • Tabs vs spaces: YAML indentation must use spaces, never tabs.
  • Indentation: keep nested levels consistent, usually two spaces per level.
  • Colons: a colon inside a value needs a space after it (key: value).
  • Quotes: wrap values with special characters like # or : in quotes.

YAML to JSON FAQs

What is the difference between YAML and JSON?
YAML is a human-friendly configuration format that uses indentation instead of brackets. JSON is stricter and machine-oriented, using braces, brackets and quoted keys. Both describe the same data, which is why conversion is lossless for most documents.
Why convert YAML to JSON?
Many APIs, JavaScript apps and config tools only accept JSON. Converting lets you write comfortably in YAML and paste strict JSON where it is required.
Is my YAML uploaded anywhere?
No. Parsing and formatting happen in your browser with the js-yaml library. Your data never leaves your device.
Does it support nested YAML and multiple documents?
Nested objects, arrays and all standard YAML types are supported. Multi-document files separated by --- convert to a JSON array of documents.
What do I do when I get a parse error?
The error box shows the exact message from the parser, usually with a line and column. The most common cause is mixed tabs and spaces: YAML requires spaces for indentation.
